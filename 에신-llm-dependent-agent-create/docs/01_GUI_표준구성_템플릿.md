## 1. 폴더 구조 표준

**원리 — 루트에는 실무자가 볼 것만 둔다. 개발 문서는 별도 폴더로 격리한다.**

```
받는 폴더/
├─ 시작.bat                              ← 유일한 진입점, 두 번 클릭
├─ README.md                             ← 문서 안내 지도(무엇을 언제 보는지 표)
├─ CLAUDE.md                             ← 헌법 12조 + 반복 함정 + 구조 + 검증 명령 (고치는 사람용)
├─ 「사용자 매뉴얼(설치 및 사용법)」.html   ← 0~8부, 화면 안 [사용자 매뉴얼] 버튼으로도 열림
├─ 「이번에 바뀐 것(날짜)」.md             ← 이번 판 릴리스 노트 (실무자용)
├─ 「확인이 필요한 사항 목록」.md          ← 법령·실무 근거를 못 구해 비워 둔 항목
├─ app/                                  ← 프로그램 본체. 실무자는 열 일 없음
│  ├─ ui.py · ui/index.html              ← 로컬 웹 GUI (§2·§3)
│  ├─ engine.py                          ← LLM 호출·자율 루프 (§4)
│  ├─ rules.py                           ← 결정론 계산 (§4)
│  ├─ store.py                           ← 접수대장·이력·잠금 (§4)
│  ├─ law.py · lawcheck.py               ← 로컬 법전·인용 조문 대조 (§4)
│  ├─ vault.py                           ← 지식 볼트 + 사람 게이트 (§4)
│  ├─ uicontract.py                      ← 화면-서버 계약 (§4)
│  ├─ standards.py · office.py           ← 실무 기준·사무소 설정 json (§4)
│  ├─ deed_form.py · deed_annex.py       ← 법정 서식 조립 (§4, 결정론)
│  ├─ backup.py · setup_helper.py        ← 자동 백업·설치 도우미 (§4)
│  ├─ run.py                             ← 터미널 CLI 병행 진입점 (§4)
│  ├─ skills/*.md + forms/ + *.json      ← 지식베이스 SSOT (§5)
│  └─ (cases/ uploads/ logs/ vault/ backups/ history.json 등 — 실행 중 자동 생성, .gitignore)
├─ runtime/                              ← 내장 파이썬 3.12 + 의존 패키지 (§2)
└─ _개발자료/                             ← 설계 문서·QC·테스트·툴. 실무자는 열 일 없음
```

**루트 문서 5종의 역할**

| 문서 | 대상 | 역할 |
|---|---|---|
| README.md | 실무자 | 나머지 문서로 가는 지도. "무엇부터 보면 되나" 한 줄 안내 + 문서별 표 |
| CLAUDE.md | 고치는 사람(제조자) | 절대 규칙(헌법) + 반복된 함정 + 검증 명령 — §6에서 상술 |
| 사용자 매뉴얼(...).html | 실무자 | 설치~일상 사용 전체. 화면 우측 상단 버튼으로도 접근 |
| 이번에 바뀐 것(날짜).md | 실무자 | 이전 판 대비 변경점만 — 매뉴얼 전체를 다시 읽지 않아도 됨 |
| 확인이 필요한 사항 목록.md | 실무자 | "몰라서 빠뜨린 것"이 아니라 "알고 비워 둔 것" — §8에서 상술 |

**`app/` 안 모듈 분리 원칙** — 기능 경계마다 파일을 가른다(한 파일에 다 넣지 않는다). 이 프로젝트는
LLM 호출(engine)·결정론 계산(rules)·저장(store)·법령(law/lawcheck)·지식게이트(vault)·화면계약
(uicontract)·설정(standards/office)·서식조립(deed_form/deed_annex)·부대기능(backup/setup_helper)·
CLI(run)로 10갈래를 나눴다. 분리 기준은 "LLM이 손대는가/안 대는가"와 "누가 이 파일을 고치는가"다.

**`runtime/` 내장 파이썬을 함께 보내는 이유** — 받는 사람 PC에 파이썬이 있는지 확신할 수 없다.
`시작.bat`이 `runtime\python.exe`를 시스템 파이썬보다 먼저 찾게 하면, 받는 사람은 아무것도
설치하지 않고 더블클릭만으로 뜬다. 지워지거나 손상되면 `시작.bat`이 인터넷으로 다시 받는다
(`setup_runtime.ps1`).

**`_개발자료/` 격리 이유** — 개발 규칙·QC 보고서·테스트가 실무자 눈에 띄면 "내가 볼 것이 아닌
것"으로 화면이 붐빈다. 공증 에이전트는 2026-09-03에 `app/vault_규칙.md`(개발 규칙)가 실무자
폴더에 잘못 놓여 있던 것을 발견해 `_개발자료/_design/`으로 옮긴 이력이 있다 — **개발 산출물이
실무자 경로에 남아 있는지 출하 전에 점검**하라는 교훈.

## 2. 기동 경로

```
시작.bat (더블클릭)
  │  chcp 65001 · PYTHONUTF8=1 · pushd 자기 위치
  │  파이썬 선택: runtime\python.exe → 시스템 python → py -3 → (없으면 setup_runtime.ps1로 준비)
  ▼
app/ui.py  main() — ui.py:3035
  │  1) terminate_previous() — ui.py:383
  │     좀비 서버 3중 탐지: ①ui.lock PID ②PowerShell Win32_Process 명령줄 매칭
  │     ③Get-NetTCPConnection 포트 소유자 → taskkill /F /T /PID
  │  2) ThreadingHTTPServer(("127.0.0.1", 7730~7741), Handler) — 루프백 전용, 12회 폴백
  │     Windows allow_reuse_address=False로 이중 바인딩 차단
  │  3) 토큰 발급 secrets.token_urlsafe(24) — 최초 접속 ?t=<토큰> → HttpOnly 쿠키 승격 → 302
  │  4) _write_lock(port) — ui.lock에 pid·port·instance·시각 기록
  │  5) 브라우저 자동 오픈 (NO_BROWSER=1로 억제 가능)
  ▼
브라우저 — http://localhost:7730 (쿠키 승격 후 깨끗한 주소)
  │  최초 실행 PC → 화면 가운데 「설치 도우미」 자동 펼침
  ▼
설치 도우미 (app/setup_helper.py)
  1 Claude Code 설치 창 열기  2 로그인 창 열기  ← 사람이 직접
  3 Codex 설치·로그인         4 자료 읽기 도구(OCR/STT/hwp)  ← "Claude Code에게 해 줘"로 위임
  실행은 화이트리스트만: _명령표 dict(setup_helper.py) 밖의 키는 전부 거부
```

**"화면은 마지막 하나만" (`terminate_previous`)** — `시작.bat`을 여러 번 누르면 창이 계속 쌓이는
사고를 막는 장치. 기본값은 "포트가 이미 쓰이면 조용히 다음 포트로 물러나기"가 아니라 **막고
사람에게 알리고 종료**다(exit 1) — 여러 개 동시 실행이 필요하면 환경변수로 명시적 예외를 준다.

**`시작.bat`은 ASCII 전용** — Windows cmd가 `.bat`을 시스템 코드페이지(cp949)로 읽기 때문에,
UTF-8 파일에 한글이 있으면 줄 디코딩이 깨져 토큰 오류가 폭주한다. 그래서 사람이 볼 한국어
안내는 전부 `app/ui.py`가 콘솔/화면에 출력한다(`PYTHONUTF8=1`로 안전). 같은 이유로 본체 폴더
이름 자체도 ASCII인 `app`을 쓴다(폴더명을 `.bat`에 적어야 할 일이 생기지 않도록).

## 3. 화면 구성

**단일 페이지 = 헤더 + 3단 그리드.** 헤더(`<header class="masthead">`, index.html:839) = 좌측에 에이전트 이름 `<h1>` + 버전 배지 + 「Desktop · Owner」(로컬 전용) 배지, 우측에 연결 상태 배지(`#conn-badge`). 헤더 바로 아래에서 3단이 시작되고 사이에 다른 띠를 두지 않는다(원본 주석: "지붕 바로 아래에서 기둥이 시작된다"). 유의사항은 맨 아래 `.footer-line`으로 내린다.

**3단 그리드** (`ui/index.html`, `.grid` — `grid-template-columns: 340px 1fr 344px`):

| 열 | 내용 | 스크롤 |
|---|---|---|
| 좌 (`.col-left`) | 이 프로그램이 **무엇으로 일하는가** — 페르소나·LLM 3자리·도구·지식베이스 4경로 | 독립(sticky) |
| 중 (`.col-mid`) | 작업 공간 — 실제 작업 화면 (흰 종이 배경). 작업을 열기 전엔 비어 있음 | 본문 스크롤 |
| 우 (`.col-right`) | 이 작업이 **어디까지 왔는가** — 설정·**작업 목록**(공증 실물에서는 「사건 목록」 — 도메인 어휘, 일반 규격은 「작업 목록」)·목표·진행 단계·안전 체계·작업 로그·기한 관리 | 독립(sticky) |

원리는 "양옆은 읽는 곳, 가운데는 하는 곳"이다. 누르는 곳은 우측 `+ 새 작업`(공증: `+ 새 사건 접수`)과 양옆 맨 위
버튼 셋(상태 새로 고침·사용자 매뉴얼·설치 도우미)뿐 — 작업을 고르는 것도 우측 작업 목록에서 한다.

### 3-1. 화면 구성 고정표

> **표는 `checklists/gui_고정표.md` 한 곳에만 있다**(중복 사본 금지 — 3곳에 두었다가 서로 달라진 실사고 2026-09-17). 조립할 때도, V1 이 대조할 때도 그 파일을 연다.

**단계 흐름 (9단계, 가운데 칸 진행)**

```
1.사건 접수 → 2.유형 판단 → 3.정합성 체크 → 4.초안 작성 → 5.교차 검증
  → 6.공증 서류 확인 → 7.사건 기록 저장 → 8.서류 인쇄 → 9.공증인 검토
```
공증인이 9번 「검토 통과」를 누르면 마지막 칸까지 완료 표시된다. 사건을 다시 열면 저장된
기록에서 단계를 되살리되, **기록에 없는 단계는 "기록 없음"(회색)으로 남긴다** — 짐작으로 완료
표시를 채우지 않는다.

**준비 상태 패널** (좌측, `verifyRows`·`skillsRow`·`lawRow`·`apiRow`·`mcpRow`·`renderProbeRows`
— `index.html:3933~4297`) — 칩 3~4단계로 표시: 초록(`.st-ok`, 되고 있다) / 노랑(`.st-warn`, 사람이
봐야 한다) / 회색(`.st-dim`, 할 일이 없다 또는 확인 중). **핵심 원칙 — 설치확인 ≠ 작동확인.**
`shutil.which()`·`importlib.util.find_spec()`은 "깔려 있는가"만 답한다. 로그인까지 됐는지는 LLM을
실제로 한 번 불러 봐야 안다 — 그래서 "확인됨/없음" 2단이 아니라 "확인 중"이 별도로 존재한다.

**액션봇(FAB + 플로팅 패널)** — `.chat-fab`(`index.html:278`)·`.chat-panel`(`:299`)·
`.chat-head`(`:323`). 버튼은 몸통 아무 데나 잡아 드래그(`cursor:grab`/`grabbing`), 창은 헤더
줄만 잡는다(본문을 잡으면 답변 텍스트를 드래그 선택할 수 없게 되므로). 여기서는 **조회 전용
Q&A**로 구현돼 있다 — 사건 필드를 바꾸거나 상태를 전이시키지 않고, 법령·조문만 근거로 답하며
근거가 없으면 "본 도구의 법령 자료에 없습니다"로 답한다(§9에서 이 지점의 표준 미달을 짚는다).

**로그 행위자 구분** — `ACTOR = {CLERK:"사무원", SYSTEM:"시스템", NOTARY:"사무원(공증인 지시)"}`
(`index.html:3192`), 기록 함수 `audit(msg, role)`(`:3554`). 사람이 누른 것과 화면이 스스로 되살린
것을 문구로 가른다(예: "시스템 · 저장된 기록을 화면에 되살림").

**pollJob 상수** — `POLL_MS = 1200`, `GIVE_UP_MS = 5000`, `GIVE_UP_AFTER = ⌈GIVE_UP_MS/POLL_MS⌉ = 5`
(`index.html:6132-6134`). 과거 `catch(e){ return; }`로 오류를 삼켜 화면이 "실행 중"에 영구 정지하던
결함(결함 74)을, 재귀 `setTimeout` + 실패 횟수 카운트 구조로 고쳤다 — `failures < GIVE_UP_AFTER`
동안만 계속 재시도.

**작업 목록**(공증 실물 명칭 「사건 목록」) — 우측, "진행 중"/"완료" 두 묶음(평소엔 접혀 건수만). 완료 묶음 아래에만 검색이
있다(진행 중은 몇 건 안 되므로). **작업 재활용(공증: "이 건으로 새 사건 만들기")**은 채우는 필드(약
44개: 당사자·금액·계약 조건 등)와 **의도적으로 비우는 필드**(6개: 상담 내용[AI 판단 오염 방지]·
작성일·확정일자부번호·번역인서약완료·공증번호·초안/검증/처리이력)를 명확히 가른다 —
`reuseCase(caseNo)`(`index.html:9199`).

**사용자 매뉴얼 버튼** — 우측 상단, 매뉴얼 html을 새 탭으로 연다. **고지사항** — 화면 맨 아래
접이식(`<details id="third-party-notice">`, `index.html:3022`)에 사용된 오픈소스 5종(pypdf·
faster-whisper·pytesseract+Tesseract·pyhwp)의 라이선스를 명시 — 별도 파일로 보내지 않는다.

**유의사항** — 좌측 상단 "하는 일"·"근거" 두 줄 + 접이식 "판단 및 작성 방법"(`index.html:880`).
"하지 않는다" 목록은 여기 두지 않는다 — 우측 "안전 체계"와 중복되므로 역할을 가른다(§6).

## 5. 지식베이스 SSOT

```
app/skills/*.md          ← 유형(도메인 케이스 10종)별 SSOT 한 파일씩 — 요건·서식·판단 힌트
app/skills/forms/         ← 법정 서식 원본(별지 65종 중 실제 쓰는 것)
app/skills/법률어_사전.json ← 일상어 → 전문 용어 약 90개 매핑
app/law_corpus.json        ← 로컬 법전(11개 법령 3084조), 하루 1회 자동 갱신
```

프롬프트가 이 파일을 읽는 경로는 두 갈래로 나뉜다.

- **① 직접 주입** — 판단할 유형이 정해지면 그 유형의 `skills/*.md`와 관련 `forms/`를 프롬프트에
  통째로 넣는다("항상 넣는 것" — 그 유형의 요건·서식).
- **② RAG(그때그때 검색)** — 상담 내용에서 조문을 찾아 넣는다(`law.find()`). 일상어 검색을 위해
  `법률어_사전.json`으로 검색어를 넓힌다(예: "회의록"→"의사록"). 무엇으로 넓혔는지는 로그에
  "검색어 넓힘: 회의록→의사록"처럼 남긴다.

두 경로 모두 **인터넷을 타지 않는다**(폴더 안 파일만 읽음). 인터넷을 쓰는 것은 법전을 최신화할
때(`law.maybe_refresh_corpus()`, 하루 1회 배경)와 법전 밖 법령을 대조할 때(MCP, 평소 호출 0회)뿐이다.

## 7. LLM 호출 방식

- **구독 CLI 호출만** — `subprocess`로 `claude`/`codex` 바이너리를 부른다. `engine._sub_env()`가
  하위 프로세스 환경변수에서 `ANTHROPIC_API_KEY`·`OPENAI_API_KEY` 등 API 키 계열을 **명시적으로
  제거**한다 — 실수로 상속돼 과금 경로가 열리는 것을 막는다.
- **폴백 없음(fail-closed)** — 2026-08-31 PO 결정으로 provider 간 폴백을 제거했다. Claude 호출이
  실패하면 이전 초안이 있으면 그것으로 완만히 물러나고(graceful degrade), 없으면 에러를 그대로
  보고한다. Codex(2차 검증)가 없으면 "미실시"로 표시할 뿐 대체 검증을 만들어내지 않는다.
- **도구 분리** — 판단·초안·1차 검증·채팅 호출은 전부 `_NO_TOOLS`로 도구 0개. 유일하게 도구를
  쓰는 것은 lawcheck의 MCP 호출이며, 그것도 `_ALLOWED_TOOLS`로 `legal_analysis` 하나만 허용한다.
- **재시도 vs 재작성을 구분** — 네트워크성 재시도(`RETRY_ATTEMPTS=3`, `RETRY_DELAY_S=2`)와 품질
  미달로 인한 재작성(`_MAX_REGEN=3`, 95점 미만)은 다른 카운터다. 둘을 합치면 "왜 이렇게 오래
  걸리나"를 설명할 수 없게 된다.
