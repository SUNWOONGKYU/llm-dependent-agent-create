## 💳 LLM 호출 비용 원칙 — 제작 ↔ 런타임 분리 (타협 불가)

**"에이전트를 만드는 것"과 "만들어진 에이전트가 돌아가는 것"은 완전히 별개다. 제작은 인프라 A/B와 무관하게 항상 로컬·구독으로 한다. 인프라 A/B는 *산출물의 런타임*에만 해당한다.**

- **제작·검증 LLM = 항상 구독(클로드 코드 본체).** 기획(문답)·발굴·조립·실호출 검증은 전부 로컬·구독으로 수행. **A/B 불문, 제작·검증 단계에 API 키·크레딧 사용 금지.** (검증하려고 API를 호출 → 크레딧 잔액 부족(400)으로 막히는 사고 — 2026-06-14 고문서 해석기 회고. 메모리 `feedback_dev_use_subscription_not_api`와 일치.)
- **산출 에이전트의 런타임 LLM** = 인프라로 결정:
  - **A (포털·서버)** → **API 키** (서버에서 불특정 다수가 호출, 사업이 비용 부담). `api/run.py` + BOM 🔵 LLM 폴백 체인(`llm_providers.py`) 그대로.
  - **B (로컬 .py)** → **`claude` CLI(구독 OAuth) 작업·1차 검증 → `codex` CLI 2차 검증·폴백. 다른 CLI 없음.** 남에게 배포할 때만 API 키. 구독 강제는 `_sub_env()`로 환경의 `ANTHROPIC_API_KEY` 제거 후 CLI 호출(무효 키가 API 모드로 끌고 가 막히는 사고 차단), CLI는 `cwd=tempfile.gettempdir()`로 세션로그 격리. 참조 구현(제작자 로컬 예시 — 경로가 없으면 위 서술만으로 충분): (제작자 선행 구현 — `templates/llm_skeleton.py` 에 옮겨져 있음).
- ⚠️ **BOM 🔵 `llm_providers.py`(API 키 폴백 체인)는 인프라 A 런타임의 표준 자산이다. 인프라 B(로컬)에는 API 폴백 체인 대신 `claude`·`codex` CLI(구독, 두 종) 호출을 표준으로 한다.**

## 출하 형태 — 2가지 구동 방식 (V3.13 — 9종에서 축소)

이 공장은 **LLM(두뇌) 의존형 에이전트** 한 종(種)만 제조한다. 그 에이전트가 *어디서 어떻게 구동되는지*는 2가지로만 가른다 — 인프라 A/B 분기(Phase 0)와 그대로 짝을 이룬다.

| 구동 방식 | 적합 조건 | 인프라 |
|----------|----------|--------|
| **웹사이트형** | 서버 호스팅 → 브라우저 접속. 단일 에이전트든 1 호스팅에 N개(카탈로그·공통 인증·관리자 콘솔, 구 "포털형")든 전부 이 안에 포함 — 서버에 떠서 브라우저로 접속한다는 점이 같다 | A |
| **데스크톱형** | PC 설치 · 로컬 파일 접근 · 민감 데이터 · **★V3.9 로컬 웹 GUI 기본 출하**(터미널만으로 내지 않는다 — Phase 6 「로컬 GUI(웹) 출하 표준」) | B |

### 구동 방식 결정

```
LLM(두뇌) 의존형 에이전트를 만든다
  │
  ├─ 서버에 떠서 브라우저로 접속하나? (에이전트 1개든 N개 카탈로그든 동일)
  │   YES → 웹사이트형 (인프라 A)
  │
  └─ PC에 설치해서 로컬로 도나?
      YES → 데스크톱형 (인프라 B)
```

판별이 모호하면 Phase 1 10라운드 + α 문답 결과로 결정하고, 그래도 모호하면 PO에게 AskUserQuestion으로 확인한다.

**V3.13 정정 — 폐지 사유**: 구 9종(사람 개입형 5·무인 자율형 3·포털형 1) 중 웹사이트형·데스크톱형을 뺀 7종(모바일앱형·메신저봇형·확장·애드인형·데몬형·API엔드포인트형·스케줄·트리거형·포털형)은 이 공장의 정식 출하 형태에서 제외한다(PO 지시, 2026-08-26). 실제 제조 실적이 이 두 형태에 집중돼 있고, 나머지는 판별 트리·QC 체크리스트만 무겁게 하면서 실사용이 없었다. 그런 요청이 들어오면 Phase 1에서 웹사이트형/데스크톱형 중 가장 가까운 쪽으로 편입하거나(예: 메신저봇형 → 데스크톱형 상주 스크립트, API엔드포인트형 → 웹사이트형 API 라우트), PO에게 범위 밖임을 알리고 확인받는다.

겹치는 항목(페르소나·목표·LLM·지식베이스·도구·안전 체계[종료·보안·비용]·루프)은 같은 개념의 다른 시점 표현 — Phase 1에서는 PO에게 묻고, Phase 6a에서는 코드로 구현.

**구현 7요소 (Phase 6a, V3.13 확정)** — 정의: *사전에 설정된 목표를 향해 LLM이 스스로 판단하고, 지식베이스를 활용하며, 도구를 사용하면서 자율 루프를 돌려 작업하되, 고유한 페르소나로 응답하고 안전 체계 안에서 동작하는 시스템* (가이드#a1 정의와 일치):
- **목표** — 달성해야 할 결과 + 완료 기준
- **LLM(두뇌, ★V3.19 = 액션봇)** — 계획·판단 엔진 (LLM API 연결). 판단하는 쪽 — 「용어 체계」 참조
- **지식베이스** — 판단·작업에 활용하는 지식의 전체 체계. 경로 4종 — ① 직접 주입(시스템 프롬프트·지시·스킬·규칙 파일) ② RAG(지식 볼트·벡터 검색) ③ API(외부 조회) ④ MCP(표준 연결). 여기에 **작업 지식 = 메모리** 가 더해진다 — 단기(컨텍스트) + 장기(외부 저장소 — 로컬·DB·벡터·클라우드). 구현 시 메모리는 지식베이스 하위 항목으로 반드시 설계한다.
- **도구** — 외부에 영향을 미치는 수단 (API·코드·브라우저). 데스크톱형은 이 도구들을 호출·순서화하는 오케스트레이션 실행체(보통 파이썬) 자체가 도구 표 최상위 항목이다 — 개별 도구 나열만으로 끝내지 않는다.
- **자율 루프(★V3.20 = State Machine + 액션봇의 합작, 단독 아님)** — 「용어 체계」 참조. State Machine(무판단 스케줄러)이 다음 단계를 결정론적으로 고르고, 그렇게 호출된 각 단계 안에서 액션봇(LLM)이 실제 판단을 한다 — 현재 상태 파악→계획→실행→결과 확인→평가→수정→재실행, 목표 달성까지 반복 (ReAct 등). **최소 회로(의무)**: 매 실행마다 산출물 생성 → `self_critique` 1~5점 자가평가 → 점수 < 임계(기본 3)이면 부족 항목을 짚어 행동을 재선택(프롬프트 보강·도구 재호출·LLM 폴백)하고 재생성 → 재평가, 최대 N회(기본 3, Phase 1 🛑종료 조건에서 확정) → 수렴 또는 graceful degrade. **단순 1-shot 호출은 '자율 루프 있음'으로 인정하지 않는다.**
- **페르소나** — 이 에이전트만의 정체성·어조·전문가 시점. system_prompt에 명시(예: "너는 ~ 분야 전문가다. 확신 있는 어조로 답하되 모르는 건 모른다고 말한다"). 웹사이트형처럼 다수 에이전트가 엔진을 공유하면 공통 기본선(엔진 조립 지점 1곳)에 개별 차별화(에이전트별 system_prompt)를 얹는 하이브리드 구조가 된다. ⚠️ 「pro-persona-debate」(전문가 페르소나 토론, 검증 기법)와 이름이 겹치지만 다른 개념이다 — 그것은 검증 방법, 이것은 에이전트의 응답 정체성.
- **안전 체계** — 위험·불법 요청 거절, 확인 안 된 사실 단정 금지, 비가역 작업 fail-closed(「비가역 작업 안전 primitive」 참조), 도구 화이트리스트. Phase 1 🔐보안 요구 답변이 이 요소의 입력이 된다.

**7요소를 모두 갖춘다 — 하나라도 빠지면 에이전트가 아니다.**

⚠️ **구현 7요소에 안 보이는 "이름"과 "분류"는 Phase 8 자산화 단계의 헌법 등재·출하 보고서에 명시되어야 한다** — 코드 안에는 안 들어가도 자산 식별에는 필수.

4. `ui.py` 실행

### ★ 인프라 B Windows 어댑터 체크리스트 (V3.5 신설 — claude-news-agent .bat 인코딩 사고)

Windows cmd는 `.bat` 파일을 기본 시스템 코드페이지(한국: cp949/MS949)로 읽는다. UTF-8(BOM 없음) `.bat`에 한글이 있으면 줄 디코딩이 깨져 `'위' is not recognized as an internal or external command` 같은 토큰 오류 폭주.

**B 인프라 Windows `.bat` 작성 의무 룰**:
1. **`.bat` 내 한글 echo·주석 금지** — 모든 사용자 메시지는 영문 (예: `echo Done.`, `echo [ERROR]`)
2. **한글 경로 하드코딩 금지** — `cd /d "…\한글 경로\..."` 대신 `pushd "%~dp0"` (.bat 자기 위치로 자동 이동)
3. **`timeout` → `ping -n N 127.0.0.1 > nul`** — `timeout`은 stdin 리디렉션 환경에서 "Input redirection is not supported"로 실패
4. **PYTHONIOENCODING/PYTHONUTF8 강제** — Python 호출 전 `set PYTHONIOENCODING=utf-8` + `set PYTHONUTF8=1`
5. **`chcp 65001 > nul`** — Python stdout이 한글일 때 콘솔 표시용 (Python 내부에서는 위 PYTHONUTF8이 본질)
6. **Python 스크립트는 stdout/stderr UTF-8 재구성** — `sys.stdout.reconfigure(encoding="utf-8", errors="replace")` 첫 줄 근처에
7. **★V3.9 신설 — 사람 개입형이면 로컬 웹 GUI를 함께 낸다** — `.bat`·터미널 진입점만 만들고 끝나지 않는다. 위 「로컬 GUI(웹) 출하 표준」 적용 조건에 걸리면 `ui.py` + `ui/index.html` 을 표준 산출물로 포함하고, `시작.bat` 이 `ui.py` 를 띄우게 한다. (회고 사유: 제작자 실제 출하 사례 2026-08-01 — 인프라 B 표준을 그대로 따랐더니 변호사·본인 신청자가 쓸 도구가 `usage: agent.py [-h] {init,status,...}` 화면으로 출하됨)

**`.bat` 저장 인코딩 — BOM 없는 UTF-8 유지**: cmd.exe가 BOM 토큰을 명령으로 오인해 `@echo off`를 무효화할 수 있다. (룰 1번과 짝 — 사용자에게 보일 한국어는 전부 파이썬 화면에서 낸다.)

검증: `cmd /c "your.bat"`을 cmd 환경에서 직접 실행했을 때 PowerShell과 동일하게 작동하는지 반드시 확인. PowerShell에서 통과해도 cmd(=더블클릭 환경)에서 실패할 수 있다.

**구조의 핵심 — 분리형이 A↔B 이동을 무비용으로 만든다**:

| 항목 | A | B |
|---|---|---|
| INSTRUCTION 본문 | `agents.system_prompt` (Supabase) | `skills/*/SKILL.md` (로컬 파일) |
| 같은 자료? | ✅ — `sync_skills.py`가 SSOT를 양쪽에 적용 |
| 엔진 코드 | `api/run.py` (Vercel Serverless) | `engine.py` (로컬 CLI) — 같은 패턴 |
| 자가평가 | self_critique 호출 | engine.py에 같은 self_critique 이식 |
| 메모리 | `conversations` 테이블 | `history.json` 파일 |
| 도구 round-trip | OP_TOOLS 등록 | engine.py 내장 (간소화 8 도구) |

**B → A 승격 (사용자 늘어서 포털 필요 시)**:
1. `스킬스/*/SKILL.md`를 `sync_skills.py`로 Supabase `agents` 테이블에 INSERT
2. `웹사이트/` 폴더에 페이지·api/run.py 배포
3. **에이전트 본체(INSTRUCTION)는 0 변경** — 같은 마크다운 그대로

**A → B 다운로드 (개인 사용 원하는 PO)**:
1. `skills/{NEW_CODE}.zip`을 다운로드 (B 분리형 패키지)
2. `python run.py {AGENT_CODE} {input}`로 PC에서 실행
3. 같은 도메인 지식·같은 LLM·같은 자가평가 — 인증·과금만 없음

### 구동 방식별 제작 요점

- **웹사이트형** — 서버 호스팅 + 브라우저 UI. 단일 에이전트면 6a만, **N개 에이전트를 한 도메인에 진열하는 포털 제조 모드(1c)면 6a+6b+6c 모두 필수**(구 "포털형" 흡수). 실패 정책은 「비가역 작업 안전 primitive」 참조

## ★V3.12 신설 — 실행 환경 probe·호출 규격 (Phase 6~7 필수)

> 아래는 전부 **실제 실호출에서 터진 것**이다. 단위 테스트는 통과하고 실운영에서 죽는 구간.

### 1) CLI capability probe (구독 CLI를 쓰는 모든 에이전트)

실행 **전에** 탐지하고 snapshot을 남긴다: `binary 경로 · version · 로그인 상태 · 지원 flag · 구조화 출력 지원`
모델·플래그를 하드코딩하면 CLI 업데이트에 죽거나 의도하지 않은 과금 경로를 탄다. 실제 backend와 model을 감사 로그에 남긴다.

### 2) Windows npm CLI 실행 파일 탐지

PowerShell에서 도는 `codex`는 `codex.ps1`이라, Python `subprocess(shell=False)`는 **확장자 없는 shim을 못 찾아 `WinError 2`로 죽는다.**
`where`/`shutil.which` 결과와 npm 패키지 구조를 검사해 **단일 `.exe`를 절대경로로** 선택한다. `.cmd`·PowerShell 경유·`shell=True` 우회 금지(주입 위험). 못 찾으면 probe에서 중단.

### 3) 공급자별 strict JSON Schema 정규화

Pydantic 기본 스키마를 그대로 보내면 공급자가 거부한다(실제: `additionalProperties` 생략·`format: uri` 거부 → 400).
전송용 스키마는 **모든 object에 `additionalProperties: false` + 전체 required를 재귀 적용**하고 미지원 format을 제거한다. 응답은 원본 모델로 다시 검증한다. 짧은 live structured-output probe를 출하 게이트에 둔다.

### 4) 웹 LLM 응답 봉투 허용 + 다중 JSON 거부

웹 UI LLM은 유효한 JSON 앞뒤에 설명 문장을 붙여 반환한다.
전체 파싱 우선 → 실패 시 `raw_decode`로 **정확히 하나의 완전한 JSON만** 허용. 0개·2개 이상·잘린 값은 fail-closed. 임의 문자열 추출은 금지(설명 속 예시 JSON을 잘못 채택한다).

### 5) Windows PowerShell 5.1 스크립트 인코딩 게이트

BOM 없는 UTF-8 스크립트의 한글은 PowerShell 5.1에서 깨져 **파싱 단계에서 설치가 실패**한다(정적 검사로는 안 잡힌다).
설치·제거 스크립트는 **ASCII-only 기본**, 한글이 필요하면 **UTF-8 BOM 저장을 검증**한다. 실제 5.1 파서와 설치 명령을 모두 실행해 확인한다. 사용자 표시 문구는 GUI에 두고 스크립트는 기계 계약으로 제한.

### 6) 실행 시간 제한 — 금지 대상 명확화

금지는 **대기용 `timeout.exe`** 사용이다. **실행 deadline과 자식 프로세스 트리 종료는 의무**다. 둘을 혼동해 실행 제한까지 없애면 예산을 넘는 프로세스가 남는다.

### 7) 설치·실행·외부 설정 분리

- `setup`과 `launch`를 분리하고 **정상 실행 중 네트워크 설치 금지**(재현성·공급망)
- 바로가기·Task Scheduler 등 **PC 설정 변경은 PO opt-in**
- 첫 설치 부담은 `health` 명령과 명확한 setup 안내로 보완

### 8) 채택 공급자만 실호출

QC의 실호출 검증은 **실제 채택한 런타임 공급자에만** 요구한다. 미채택 공급자의 키·비용·폴백 검증 때문에 출하가 막히면 안 된다. 폴백을 채택한 프로젝트에서만 폴백 실호출을 opt-in.

## ★V3.12 신설 — 비가역 작업 안전 primitive

### 1) 승인은 산출물에 결속한다

단순 confirm은 **승인 후 내용이 바뀌어도 통과**시킨다. 비가역 도구(게시·삭제·결제·전송)는 승인을 다음에 결속한다:

`artifact version · 전체 SHA-256 · actor · 결정 시각 · destination · scope · expiry`

하나라도 바뀌면 **승인 무효화**. 사용자가 보지 않은 본문·이미지·대상에 과거 승인이 재사용되는 것을 막는다.

### 2) 실패 정책 — fail-closed가 기본인 영역

| 작업 | 정책 |
|---|---|
| 읽기 전용 관측·조회 | 제한적 fail-open 허용 |
| **게시·삭제·승인·인증·결제** | **항상 fail-closed** |

가용성이 줄더라도 의도된 안전 우선이다.

### 3) 브라우저 세션·웹 콘텐츠 위협 모델 (웹세션을 쓰는 에이전트에 필수)

로그인 세션을 재사용하는 순간 위협이 달라진다. 검사 항목:
- **loopback 바인딩** CDP · 인증정보 비저장 · 로그 마스킹
- **웹에서 읽은 내용은 데이터로만 취급** — 명령으로 승격 금지(prompt injection)
- 도구 **allowlist** · 최종 submit 차단(사람 승인 전) · 대상 계정 확인

### 4) 생산 재시도와 QC 재생성 분리

운영 정책이 "자동 재시도 금지"인데 QC가 재생성을 요구하면 충돌한다.
**생산 retry는 MBO 옵션**으로 두고, QC는 **격리된 fake 또는 수동 승인 재실행**으로 검증한다. 실패는 실패·held 상태로 두고 사람이 판단한다.

## 시운전 (Phase 6b) — 1회 원칙

KPI 「사용자 여정」(입력 → 사람 개입 → 최종 산출물)을 증명하려고 전 과정을 **한 번** 돌린다. 제품에 약식·샘플 모드가 있으면 그것으로(없으면 만들어 둔다 — 실습·시제·검증이 전부 빨라진다).
- 시운전 중 잡은 제품 결함은 고친다. **재실행은 결함이 여정을 끊었을 때만.** 점수를 올리려고, 예쁜 결과를 보려고 다시 돌리지 않는다.
- 장 점수·라운드 수 같은 제품 내부 지표를 PO 에게 중계하지 않는다 — 제조자는 결과물 품질을 평가하는 사람이 아니다(원칙 1).
- 시운전 기록(state·산출물·로그)은 Phase 7 V1 의 사용자 여정 KPI 근거다. 검증 전 스냅샷에 포함한다.
- 시운전에서 나온 결함은 `기획안_구현_대조표.md` 의 해당 행에 「시운전 발견 → 수정」으로 남긴다.
