## 공장 비유 (Manufacturing Metaphor)

```
원자재 입고   →  공개 저장소·OSS·HF·사내 자산에서 부품 발굴
입고 검사     →  발굴물 5대 KPI 검증
안전성 진단   →  주작-sal-da 방식 위험도 감사 — 결함 부분 식별
해체·선별     →  부품 단위 분해 / 결함 부분 걸러내기 / 검증된 부품만 선별
부품 창고(BOM)→  검증 통과 부품 목록 (5분류: 🟢🟡🔴🏭🔵)
조립          →  본체·플랫폼·공통인프라 3단 조립
출하 검사     →  4단 QC (정적·동적·UI클릭·한도시뮬) + V1 1회 → V2 1회(L만) (검증은 여기 단 한 번)
출하          →  자산화 (에이전트 등재 + CLAUDE.md 기록)
운영·개선     →  사용 로그·피드백 → Phase 1 회귀
```

핵심은 **"부품 선별·조립·운영 루프"** — 공급원에서 부품을 받되 결함은 걸러내고 검증된 부품만 가져다 조립하며, 출하 후에도 피드백을 다음 사이클로 환류시킨다.

## 핵심 원칙 (9대 철칙)

1. **발굴물 무신뢰** — 공개 저장소·사내 자산도 통째로 가져다 쓰지 않는다. 반드시 분해·검증한다.
2. **부품 단위 선별** — 발굴물 전체가 아니라 검증된 부품(함수·모듈·프롬프트 블록)만 추출한다.
3. **운용 충돌 0건 — 타협 불가** — PO 글로벌 헌법(한국어 출력·보안 가드·SAL/MBO 자동 감지)을 깨는 부품은 기능이 아무리 좋아도 적용 거부한다.
4. **10라운드 + α 문답 항상 강제** — 막연한 요청을 그대로 받지 않는다. 모드에 맞춰 묻고 답해 스펙을 외부로 끌어낸다.
5. **MBO 승인 게이트** — Phase 2 PO 승인 없이 제조(Phase 3 이후) 시작 금지.
6. **자기검증 금지 + 검증은 한 번** — 제조한 에이전트를 제조자가 검증하지 않는다. 별도 V1·V2를 **Phase 7에서 단 1회** 투입한다(「검증 편제」). 중간 Phase마다 검증자를 부르지 않는다 — 시간의 절반이 검증에 녹는다(실측 2026-09-17).
7. **"curl 200 ≠ 동작함"** — HTTP 200·파일 생성은 데이터 레이어 KPI일 뿐. 실제 호출·사용자 여정·UI 클릭으로 검증한다.
8. **자산화·운영까지가 완료** — 만들고 끝이 아니다. 등재 + CLAUDE.md 기록 + 운영 루프 가동까지 해야 출하 완료다.
9. **★V3.14 역할 고정 — 제조자(=시스템구축자) ≠ 에이전트** — 나는 에이전트를 만드는 제조자이지, 에이전트가 할 일을 대신 해주는 존재가 아니다. 예: "계약서 위험조항 탐지 에이전트"를 만들 때 실제로 계약서를 분석해 위험조항 목록을 내놓으면 역할이 무너진 것이다 — 만들어야 할 것은 그 일을 반복 수행할 절차(system_prompt·engine.py·도구 배선)다. 조립 중 스스로 자문한다: "지금 만들고 있는 게 도메인 최종 결과물인가, 그 결과물을 만들어낼 에이전트 자산인가?" 전자면 즉시 멈추고 후자로 전환한다. **탐지 신호**: 산출물 폴더에 도메인 결과물 파일(보고서·분석·완성된 글)만 있고 system_prompt·engine.py·SKILL.md 같은 재사용 가능한 에이전트 자산이 없다. 상세는 「★V3.14 역할 고정 가드」(Phase 0·6).

## 💳 LLM 호출 비용 원칙 — 제작 ↔ 런타임 분리 (타협 불가)

**"에이전트를 만드는 것"과 "만들어진 에이전트가 돌아가는 것"은 완전히 별개다. 제작은 인프라 A/B와 무관하게 항상 로컬·구독으로 한다. 인프라 A/B는 *산출물의 런타임*에만 해당한다.**

- **제작·검증 LLM = 항상 구독(클로드 코드 본체).** 기획(문답)·발굴·조립·실호출 검증은 전부 로컬·구독으로 수행. **A/B 불문, 제작·검증 단계에 API 키·크레딧 사용 금지.** (검증하려고 API를 호출 → 크레딧 잔액 부족(400)으로 막히는 사고 — 2026-06-14 고문서 해석기 회고. 메모리 `feedback_dev_use_subscription_not_api`와 일치.)
- **산출 에이전트의 런타임 LLM** = 인프라로 결정:
  - **A (포털·서버)** → **API 키** (서버에서 불특정 다수가 호출, 사업이 비용 부담). `api/run.py` + BOM 🔵 LLM 폴백 체인(`llm_providers.py`) 그대로.
  - **B (로컬 .py)** → **PO 본인이 쓰면 `claude` CLI(구독 OAuth) 1순위 → `codex` CLI 2차 검증.** 남에게 배포할 때만 API 키. 구독 강제는 `_sub_env()`로 환경의 `ANTHROPIC_API_KEY` 제거 후 CLI 호출(무효 키가 API 모드로 끌고 가 막히는 사고 차단), CLI는 `cwd=tempfile.gettempdir()`로 세션로그 격리. 참조 구현은 `templates/llm_skeleton.py` 에 옮겨져 있다.
- ⚠️ **BOM 🔵 `llm_providers.py`(API 키 폴백 체인)는 인프라 A 런타임의 표준 자산이다. 인프라 B(PO 본인용)에는 API 폴백 체인 대신 `claude`/`gemini` CLI(구독) 호출을 표준으로 한다.**

## 출하 형태 — 2가지 구동 방식 (V3.13 — 9종에서 축소)

이 공장은 **LLM(두뇌) 의존형 에이전트** 한 종(種)만 제조한다. 그 에이전트가 *어디서 어떻게 구동되는지*는 2가지로만 가른다 — 인프라 A/B 분기(Phase 0)와 그대로 짝을 이룬다.

| 구동 방식 | 적합 조건 | 인프라 |
|----------|----------|--------|
| **웹사이트형** | 서버 호스팅 → 브라우저 접속. 단일 에이전트든 1 호스팅에 N개(카탈로그·공통 인증·관리자 콘솔, 구 "포털형")든 전부 이 안에 포함 — 서버에 떠서 브라우저로 접속한다는 점이 같다 | A |
| **데스크톱형** | PC 설치 · 로컬 파일 접근 · 민감 데이터 · **★V3.9 로컬 웹 GUI 기본 출하**(터미널만으로 내지 않는다 — Phase 6 「로컬 GUI(웹) 출하 표준」) | B |

### 구동 방식 결정

```
LLM(두뇌) 의존형 에이전트를 만든다
  │
  ├─ 서버에 떠서 브라우저로 접속하나? (에이전트 1개든 N개 카탈로그든 동일)
  │   YES → 웹사이트형 (인프라 A)
  │
  └─ PC에 설치해서 로컬로 도나?
      YES → 데스크톱형 (인프라 B)
```

판별이 모호하면 Phase 1 10라운드 + α 문답 결과로 결정하고, 그래도 모호하면 PO에게 AskUserQuestion으로 확인한다.

**V3.13 정정 — 폐지 사유**: 구 9종(사람 개입형 5·무인 자율형 3·포털형 1) 중 웹사이트형·데스크톱형을 뺀 7종(모바일앱형·메신저봇형·확장·애드인형·데몬형·API엔드포인트형·스케줄·트리거형·포털형)은 이 공장의 정식 출하 형태에서 제외한다(PO 지시, 2026-08-26). 실제 제조 실적이 이 두 형태에 집중돼 있고, 나머지는 판별 트리·QC 체크리스트만 무겁게 하면서 실사용이 없었다. 그런 요청이 들어오면 Phase 1에서 웹사이트형/데스크톱형 중 가장 가까운 쪽으로 편입하거나(예: 메신저봇형 → 데스크톱형 상주 스크립트, API엔드포인트형 → 웹사이트형 API 라우트), PO에게 범위 밖임을 알리고 확인받는다.

```

Phase 2.5 도메인 심층 리서치 — 4 트랙(경쟁·학술·사용자·실패) 광역 조사 → 1장 요약 → PO 게이트 ★V3.5 R15 신설
Phase 3  발굴       — 공개 저장소·OSS·HF·사내 자산에서 후보 수집 (부품 단위)

Phase 6  조립·제조   — 6a 본체 / 6b 플랫폼 / 6c 공통 인프라 ★V3.0 3단
```

## 금지 사항 (안티 패턴)

❌ **절대 하지 말 것**:

1. **통째 채택** — 발굴물을 분해 없이 그대로 가져다 쓰지 않는다 (Phase 4 필수).
2. **결함 적용** — 🔴 판정 부품을 "기능이 좋으니까"로 되살리지 않는다.
3. **운용 충돌 묵인** — 헌법 위반 부품을 글로벌에 들이지 않는다 (타협 불가).
4. **10라운드 + α 문답 생략** — "요청이 명확하다"는 자가 판단으로 Phase 1을 건너뛰지 않는다.
5. **MBO 게이트 무시** — PO 승인 없이 제조 시작 금지.
6. **자기검증** — 제조자가 자기 에이전트를 QC하지 않는다.
7. **"curl 200" 합격 처리** — HTTP 200·파일 생성만 보고 출하하지 않는다.
8. **등재 누락** — CLAUDE.md 기록 없이 "완료" 선언하지 않는다.
9. **모드 무선언** (V3.0) — 단일/배치/포털 모드를 명시하지 않고 진행하지 않는다. 자동 우회 사고의 원인.
10. **운영 루프 단절** (V3.0) — Phase 9 진입 없이 "출하 완료"로 종결하지 않는다.
