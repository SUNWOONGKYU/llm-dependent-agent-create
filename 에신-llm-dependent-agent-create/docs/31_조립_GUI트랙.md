**왜 로컬 웹인가 — 대안 비교**:

| 방식 | 추가 의존성 | 외관 | 배포 | 판정 |
|---|---|---|---|---|
| **로컬 웹 (`http.server` + 브라우저)** | **0 — 파이썬 표준 라이브러리만** | 브라우저가 그리므로 자유 | zip에 그대로 | **채택** |

| PyQt/PySide | 수백 MB | 좋음 | 무거움 | 탈락 |
| Streamlit/Gradio | pip 다수 | 무난·스타일 제약 | 무거움 | 탈락 |

결정적 장점 — **`127.0.0.1`에만 바인딩하므로 사용자 데이터가 PC 밖으로 나가지 않는다.** 개인정보를 다루는 에이전트에 특히 중요.
⛔ **Flask·FastAPI·Streamlit 도입 금지** — 표준 라이브러리만 쓰는 것이 이 표준의 취지다. 추가 설치를 요구하는 순간 무너진다.

**`ui.py` 필수 요건 8**:
1. **루프백 전용 바인딩** — `ThreadingHTTPServer(("127.0.0.1", port), ...)`. `0.0.0.0` 금지 (외부 접속 차단)
2. **토큰 인증 + 쿠키 승격** — 실행할 때마다 `secrets.token_urlsafe(24)` 생성. 최초 접속은 `?t=<토큰>`, 서버가 쿠키(`HttpOnly; SameSite=Strict`)로 옮겨 담고 `302`로 깨끗한 주소로 돌려보낸다. 이후 사용자는 `http://localhost:{포트}` 만 쓴다. *(같은 PC의 다른 프로그램이 몰래 접근하는 것을 막으면서 주소를 짧게 유지)*
3. **★V3.18 정정 — 고정 포트, 기본은 폴백 금지(중복 실행 방지)** — 기본 포트를 정한다(예 7001). **포트가 이미 쓰이고 있으면 기본값은 다음 포트로 조용히 넘어가는 게 아니라, 새로 띄우지 않고 사람에게 알리고 종료한다**(exit 1) — "화면 서버를 새로 띄우지 않았다 / 이미 떠 있을 가능성이 높다 / 기존 주소 `http://localhost:{포트}`로 접속해라 / 죽은 게 확실하면 먼저 끄고 다시 실행해라"를 콘솔에 출력. 정말 여러 개를 동시에 띄워야 하는 예외적 경우만 환경변수(예 `UI_ALLOW_MULTI=1`)로 명시하게 하고, 그때만 +1씩 최대 12회 물러나다 안 되면 임의 포트로 폴백한다(서로 다른 포트·다른 토큰이 뜬다는 점을 사람이 알아야 한다).
   - **왜 정정하나(V3.9 원문은 반대였다)**: "포트 사용 중이면 자동으로 다음 포트 물러나기"가 기본값이면, 사용자가 `시작.bat`을 여러 번 누를 때마다 매번 새 인스턴스가 다른 포트에 뜬다 — 창(탭)이 계속 쌓이는 사고. 조용히 물러나지 않고 **막고 알리는 쪽이 기본**이어야 한다("조용한 실패 금지" 원칙과 일치).
   - **Windows 전용 결함 대응(필수)**: Windows의 `http.server` 기본값 `allow_reuse_address=True`(`SO_REUSEADDR`)는 리눅스와 달리 **이미 LISTEN 중인 포트에도 다른 소켓이 바인딩되는 것을 막지 못한다** — 그래서 위 "포트 이미 사용 중" 감지 자체가 안 먹혀 같은 포트에 여러 프로세스가 동시에 붙고, 요청이 무작위 프로세스로 튀어 토큰 불일치 403이 난다(실측). `ThreadingHTTPServer`를 상속해 `server_bind()`에서 Windows에 한해(`hasattr(socket, "SO_EXCLUSIVEADDRUSE")`로 분기, 다른 OS는 기존 동작 유지) `SO_EXCLUSIVEADDRUSE`를 설정한다 — 이후 바인딩 시도는 확실히 `OSError`로 실패해 위 감지 로직이 제대로 작동한다.
   - **탭 누적 방지(개발/재시작 편의)**: 서버를 껐다 다시 켤 때마다 새 브라우저 탭이 열리면 죽은 옛 탭이 계속 쌓인다. 자동 탭 열기를 끌 수 있는 환경변수(예 `NO_BROWSER=1`)를 둔다 — 기본값(미설정)은 최초 실행 사용자를 위해 그대로 자동으로 연다.
4. **경로 탈출 차단** — 파일을 열거나 저장할 때 작업 폴더 밖이면 `403`. 업로드 파일명은 `Path(name).name` 으로 자르고 `[<>:"/\\|?*]` 치환
5. **덮어쓰기 금지** — 같은 이름이 있으면 `이름(2).pdf` 로 저장. 원본 보존이 원칙
6. **조용한 종료** — `ConnectionResetError`·`BrokenPipeError` 를 삼킨다. 탭 닫을 때마다 트레이스백이 뜨면 사용자가 오류로 오해
7. **`/favicon.ico` 204 응답** — 없으면 요청마다 404 로그가 쌓인다
8. **종료 방법을 사용자에게 알린다** — 비개발자는 서버를 어떻게 끄는지 모른다. ① 콘솔 창에 영문 한 줄(`Close this window to stop.`) ② 화면 첫 진입 안내에 한국어로 "다 쓰셨으면 검은 창을 닫으시면 됩니다" ③ 브라우저 탭만 닫아도 서버는 살아 있다는 점을 명시. 안 알리면 서버를 켜둔 채 방치하거나 임의 종료해 다음 실행에서 포트가 물린다(고정 포트 폴백 12회를 소모)

   - `is_file()`·`shutil.which()`·`importlib.util.find_spec()`는 **설치 확인이지 작동 확인이 아니다.** 원격 응답이 필요한 대상(CLI·API·브라우저 자동화)에 이걸로 "연결됨"을 표시하지 않는다. 단 **로컬 라이브러리**(호출할 원격 서비스가 없어 "설치됨=작동 가능"이 참인 것, 예 Tesseract)는 설치 확인만으로 충분 — 전부 다 실호출로 바꾸라는 뜻이 아니다
   - 실제 라이브 체크(`--version` 호출 등)를 넣을 땐 **타임아웃을 추측하지 말고 실측**한다 — 5초로 잡았다가 실제로 15초+ 걸리는 정상 응답을 "고장"으로 오판한 사고 있음
   - 라이브 체크가 여러 개면 **반드시 병렬화**(`ThreadPoolExecutor` 등) — 순차 실행 시 wall-clock이 그대로 합산된다(실측: 순차 17.5초 → 병렬 4.8초)
   - 완전한 실시간 검증이 비싸면(매 페이지로드마다 실호출은 과함) 한 단계 위(예 `--version`)까지만 확인하고 한계를 `status_detail`에 명시적으로 실토한다. **차선책으로 반응형 캐시**(실제 작업 중 실패하면 그 순간부터 "못 씀"으로 기억)도 유효한 절충안이다 — 완벽하진 않지만(한 번도 안 불려본 미인증 CLI는 여전히 오판 가능) 매번 능동적 라이브체크보다 실용적
   - 의존 목록(LLM 폴백 체인 등)에 있는 항목이 이 패널에도 다 나열됐는지 대조한다 — 폴백 체인의 실제 구성원이 카드에서 빠지는 사고가 있었다
7. **자료 업로드 3종** — 끌어다 놓기 + 파일 선택 + 작업 폴더 열기. 사용자가 폴더 경로를 직접 찾아 들어가게 만들지 않는다
8. **접근성** — 대비비 확보, 폼 요소에 라벨, `@media (prefers-reduced-motion: reduce)` 로 애니메이션 차단
9. **★V3.15 신설, ★V3.17 명명 — 액션봇(필수, 9번째 철칙 "역할 고정"의 직접 이행 장치)** — 조회만 하는 챗봇(대화만 되고 실제 작업은 못 시킴)이 아니라, 대화로 실제 도구를 호출해 작업까지 수행하는 **액션봇**을 화면 안에 둔다. 업계 표준 명칭은 아직 없지만("에이전틱 챗봇"이 그나마 가까움), 이해하기 쉬워 이 공장 안에서는 이 이름으로 통일한다. 사용자가 이 에이전트를 움직이는 **바로 그 LLM**과 화면 안에서 직접 대화할 수 있어야 한다. 이게 없으면 사용자는 매번 Claude Code(제조자)를 거쳐야만 에이전트에 지시를 내릴 수 있게 되고, 그건 9대 철칙 9번 "제조자 ≠ 에이전트"가 깨졌다는 뜻이다 — 산출물이 독립 실행되지 않고 제조자 안에 갇힌 것. **검증된 참조 구현**(제작자 로컬 사례, 2026-08-26): 우하단 고정 FAB 버튼(`.chat-fab`) → 클릭 시 플로팅 패널(`.chat-floating`, 400px 폭, ESC·재클릭으로 닫힘) 펼침. 화면의 다른 카드를 스크롤해 찾아야 하는 고정 배치 채팅창은 탈락— 어느 화면·어느 단계에 있든 스크롤 없이 즉시 열려야 실제로 쓰인다(고정 배치였을 때는 안 쓰였다는 게 실측 사유).
   - **프론트(순수 UI, 그대로 포팅 가능)** — CSS(`.chat-fab`·`.chat-fab-dot`·`.chat-floating`·`.chat-floating-head`·`.chat-floating-close`), HTML(FAB 버튼 + 헤더·닫기버튼 있는 패널 + 로그·입력창), JS 열고닫기(`openChatFloating`/`closeChatFloating`— 열 때 패널에 `.open`, FAB에 `.hidden`, 입력창 focus / 닫을 때 반대 + ESC 키 리스너), 안읽음 점(`setChatUnread` — 패널 닫혀있는 동안 백그라운드로 새 답이 오면 FAB에 점 표시, 다시 열면 꺼짐). 도메인 지식이 전혀 없어 이 4요소는 프로젝트 무관하게 그대로 재사용한다.
   - **백엔드(도메인마다 새로 구현)** — `POST /api/chat`(메시지 전송) + `GET /api/chat/log`(기록 조회) 라우트. 메시지 → **같은 LLM 호출 채널**(engine.py가 이미 쓰는 `llm.ask()`/CLI 호출, 새 연결을 따로 만들지 않는다) → 필요하면 이 에이전트의 기존 도구를 그대로 호출(tool round-trip, 최대 호출 수·시간 상한 둘 다 필수) → 대화 기록에 append → 최신 로그 반환. 장시간 작업이 걸리면 기존 폴링 라우트 계약(위 항목 3)을 그대로 재사용 — 채팅 전용의 새 비동기 메커니즘을 만들지 않는다.
   - **액션봇은 채팅 전용이 아니라 에이전트 본체 기능 전체로 들어가는 정문이다** — 조회뿐 아니라 이 에이전트의 실행·상태변경 도구까지 대화로 호출 가능해야 "역할 고정"의 대체 채널이 성립한다(대화로 조회만 되고 실제 작업은 여전히 못 시키면 사용자는 결국 다시 Claude Code를 거치게 된다).
   - **★비가역/상태변경 액션은 confirm 관문 필수** — LLM이 상태를 바꾸거나 되돌리기 어려운 액션(파일 확정·값 수정·게시 등)을 하려 하면 즉시 실행하지 않고 `needs_confirm` 신호를 화면에 반환해 "«그대로 진행»" 같은 명시적 재확인을 받은 뒤에만 실행한다. 조회형 액션엔 필요 없다. 이 관문 없이 대화만으로 상태변경까지 즉시 실행되면 「비가역 작업 안전 primitive」의 fail-closed 원칙이 채팅 경로에서만 새는 구멍이 된다.
   - **적용 예외**: 대화형 지시가 애초에 의미 없는 완전 자동 배치 처리 에이전트(사람 개입 지점이 없는 것)는 생략 가능 — 그 경우도 Phase 1에서 사유를 명시하고 PO 확인을 받는다.

**`ui.py` ↔ `engine.py` 연동 규격 (★V3.9 보강 — Gemini 교차검증 반영)**: 위 요건은 서버(`ui.py`)와 LLM 호출 본체(`engine.py`)를 각각 규정하지만, 둘이 어떻게 통신하는지가 빠지면 제조자가 매번 스스로 설계해야 한다. 다음을 규격으로 둔다.

1. **연동 방식 — 둘 중 하나를 고르고 근거를 README에 남긴다**:
   - **모듈 import (기본 권장)** — `ui.py`가 `engine.py`를 `import`해 함수로 직접 호출. 같은 프로세스라 빠르고 진행률·중간결과 같은 상태 공유가 쉽다. 대부분의 단순 에이전트는 이걸로 충분
   - **subprocess 분리 실행** — `subprocess.run()`/`Popen`으로 `engine.py`를 별도 프로세스로 띄운다. LLM 호출이 무한루프·크래시로 죽어도 웹 서버는 살아 있고(크래시 격리), 터미널 진입점(`run.py`)과 실행 경로를 그대로 공유한다. 장시간·불안정한 외부 호출이 많으면 권장
2. **최소 라우트 계약** — 화면이 필요로 하는 기능마다 엔드포인트를 정의하고 목록을 README에 적는다. 이름·개수는 에이전트마다 다르되, 예시로 다음을 둔다: `GET /` 화면 · `GET /api/status` 준비 상태(의존성 점검) · `POST /api/upload` 자료 업로드 · `POST /api/run` 실행 요청 · `GET /api/result` 결과 조회 · `POST /api/open-folder` 작업 폴더 열기 · **`POST /api/chat` 대화 전송 + `GET /api/chat/log` 대화 기록 조회 (★V3.15, 액션봇용 — 위 9번 요건)**
3. **장시간 작업은 블로킹 금지** — LLM 호출은 수십 초가 걸린다. 요청을 그대로 블로킹하면 브라우저가 멈춘 것처럼 보인다. **폴링**(`POST /api/run`이 즉시 202 + job id 반환 → 화면이 `GET /api/status?job=...`을 주기적으로 조회) 또는 **스트리밍**(SSE·chunked response로 진행 상황 실시간 전송) 중 하나를 반드시 둔다
4. **엔진 프로세스 수명 관리** — subprocess 방식이면 `ui.py` 종료 시 자식 프로세스를 정리한다(안 하면 백그라운드에 좀비로 남는다). `atexit`·시그널 핸들러로 `terminate()` 하거나, 요청마다 짧게 살고 죽는 1회성 프로세스로 설계한다

**화면 구성 고정표 — 헤더 + 3단, 블록 위치·접기까지 (★V3.10 권장 → ★V3.22 필수 → ★V3.27 고정표)**

"원본 에이전트를 참고하라"로는 같은 화면이 안 나온다 — 스킬 사용자는 그 원본을 열 수 없다(2026-09-17 실사고). **그래서 원본의 구성을 아래 표와 뼈대 파일에 전부 옮겨 적었다. 이 표가 화면이다.** 데스크톱형 GUI 는 `templates/gui_skeleton/index.html`(공증 v1.3 화면을 도메인 무관하게 옮긴 뼈대)을 `app/ui/index.html` 로 **복사한 뒤 `{{ }}` 자리와 「도메인 교체 구역」만 채운다.** 블록을 다른 기둥으로 옮기거나, 순서를 바꾸거나, 접기를 풀거나, 지우지 않는다. 없는 기능은 블록을 남기고 「이 에이전트에는 ○○이 없습니다」 한 줄로 채운다.

```
┌────────────────────────────────────────────────────────────────────┐
│ 헤더 masthead: [에이전트 이름] [v버전] [Desktop · Owner]   …  [연결 배지] │
├─────────────┬──────────────────────────────┬─────────────────────────┤
│ 좌 340px    │ 가운데 1fr — Workspace(작업공간) │ 우 344px                 │
│ 무엇으로     │ 작업을 열기 전엔 비어 있음         │ 어디까지 왔는가            │
│ 일하는가     │ 단계 카드 1…N (우측 진행 단계와 1:1)│ + 설정·목표·안전·로그      │
└─────────────┴──────────────────────────────┴─────────────────────────┘
```

> **표는 `checklists/gui_고정표.md` 한 곳에만 있다**(중복 사본 금지 — 3곳에 두었다가 서로 달라진 실사고 2026-09-17). 조립할 때도, V1 이 대조할 때도 그 파일을 연다.

- **원리 — 양옆은 읽는 곳, 가운데는 하는 곳.** 누르는 곳은 우측 [+ 새 접수]와 양옆 맨 위 버튼 셋(상태 새로 고침·매뉴얼·설치 도우미)뿐. 작업을 고르는 것도 우측 작업 목록에서.
- **폭** 340 / 1fr / 344 (우측이 조금 넓다 — 진행 단계 부연이 300px 에서 끊긴다). 사이드바는 카드 묶음이 아니라 한 덩어리 기둥(`align-items:stretch`, sticky 금지, `min-width:0`).
- **좁아질 때** 1180px 아래 2열, 760px 아래 1열. 쌓이는 순서 좌 → 우 → 중.
- **접기 원칙** — 접힌 블록은 "덜어낸 것이 아니라 감춘 것". 사람이 닫은 것은 다시 닫히게 두고, 코드는 «열기»만 한다(도구 없음·기준 빈칸·임박 항목). 연결 끊김은 아무것도 펼치지 않는다.
- **도메인 어휘로 바꿔 쓴다** — 뼈대의 「접수」「사건」「작업」은 자리 표시일 뿐이다. 논문이면 「주제·자료 입력」「논문 목록」「집필 기록」, 계약이면 「계약 등록」처럼 그 도메인 사람이 쓰는 말로 전부 교체한다(원천 도메인 어휘가 화면에 남으면 X — PO 지적 2026-09-17).
- **같은 말 두 번 금지** — 좌측 페르소나에 "하지 않는 일"을 적지 않는다(우측 안전 체계 몫). 안전 체계 줄 옆에 상태 칩을 달지 않는다(설명 반복). 접기 제목이 본문 첫 줄을 되풀이하지 않는다.
- **뼈대 JS 계약** — `VERIFY_ROWS`(LLM 3자리) · `chipRow`(found true/false/null 3값 — 설치확인 ≠ 작동확인) · `setStatusAlert` · `pollJob`(1200ms·5회) · `makeDraggable` · `chatSend`(needs_confirm) · `renderJobList` · `renderStages` · `audit`. 라우트: `/api/status` `/api/probe` `/api/state` `/api/job` `/api/chat` `/api/chat/log` `/api/open-folder` + 도메인.

> 단순한 에이전트라서 채울 블록이 없다면 그것은 GUI 트랙이 아니라 **비GUI 트랙**(docs/32)이다. GUI 트랙에 들어온 이상 고정표 블록을 줄이지 않는다(없는 기능은 「해당 없음」 한 줄).

**참고 구현**(제작자 로컬 사례 — 경로가 없으면 아래 서술만으로 충분히 만들 수 있다): (제작자 로컬 사례 — 경로 생략) (`ui.py` 약 480줄 · `ui\index.html` 약 610줄, 표준 라이브러리만). 한국 법원 서면 조판 차용 — 카드·그림자 없이 괘선 구분, 제목 바탕체, 인주 주색(`#a83224`)은 경고에만, 청자색은 확인된 항목에만, 종이 결 배경. **이 경로는 앵커가 아니라 예시다** — 위 요건 8+9(★V3.15부터, `ui.py` 8 + `ui/index.html` 9)가 규격이고, 경로가 열리지 않는 환경(공개본·타 PC)에서도 요건만으로 제조 가능해야 한다.

⚠️ **터미널 진입점(`run.py`·`agent.py`)은 삭제하지 않는다. 병행이 원칙.** 사유 4가지:
1. **자동화** — 화면은 사람이 눌러야 움직인다. 터미널은 스케줄러·다른 스크립트가 부를 수 있고, 배치(100건 반복)가 가능하다. 화면만 남기면 이 길이 막힌다
2. **화면 장애 시 우회** — 포트 충돌·브라우저 부재·`ui.py` 버그가 나도 `python run.py` 는 돈다
3. **원격** — SSH 세션에서는 그 PC의 브라우저를 띄울 수 없다
4. **디버깅** — 화면은 오류를 사용자용으로 다듬어 보여준다. 고칠 때 필요한 것은 트레이스백 전문이다

비용은 거의 0 — 이미 있는 파일을 안 지우는 것뿐이다. **단, 화면과 터미널이 같은 `engine.py` 를 불러야 한다**(연동 규격 참조). 갈라지면 같은 입력에 다른 결과가 나온다 — 그게 진짜 유지비다.
※ 이 이득은 대부분 *제작·운영자* 쪽이다. 최종 사용자(비개발자)는 터미널을 쓸 일이 거의 없다. 그래도 비용이 없으므로 남긴다.
