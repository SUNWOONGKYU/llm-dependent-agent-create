## Phase 8. 자산화·출하

만들고 끝이 아니다. 등재까지 해야 출하 완료다. (출처: SUNNY AI MAGIC 50 #18·#38)

1. **등재** — 구동 방식에 맞는 위치에 배치
2. **자산 기록** — 보유 자산 추적처(스킬 레지스트리·인덱스 등)에 1줄 등재
3. **SAL Grid 반영** — SAL_Grid_Dev_Suite 프로젝트면 grid_records JSON 갱신
4. **CLAUDE.md 헌법 등재** — 글로벌 또는 프로젝트 CLAUDE.md에 1줄 (V3.0 강조)
5. **운영 로그 인프라 가동 확인** (V3.1 신설) — Phase 9 회귀 트리거가 임계값을 감지하려면 `usage_log`·`error_log`·`feedback` 테이블/파일이 적재되고 있어야 함. 다음 3가지 확인 후 출하:
   - usage_log 테이블 존재 + 1건 이상 쓰기 검증
   - error_log 또는 동등한 에러 캡처 메커니즘 가동
   - feedback 수집 채널(관리자 콘솔 또는 외부 양식) 접근 가능
   - 이 3가지 중 하나라도 미가동 시 Phase 6c로 회귀 (인프라 우선 보강)

   **A 인프라 로그 예시 ★V3.5 후속 신설 (Medium 3)** — Supabase SQL 스키마:
   ```sql
   CREATE TABLE usage_log (
       id           BIGSERIAL PRIMARY KEY,
       agent_id     TEXT NOT NULL,
       user_id      UUID,
       ts           TIMESTAMPTZ DEFAULT now(),
       model        TEXT,
       provider     TEXT,                     -- anthropic·gemini·openai·grok
       input_tokens INTEGER,
       output_tokens INTEGER,
       latency_ms   INTEGER,
       cost_krw     NUMERIC(10,2),
       critique_score SMALLINT,                -- 1~5 self_critique
       regenerated  BOOLEAN DEFAULT FALSE
   );
   CREATE INDEX ON usage_log (agent_id, ts DESC);

   CREATE TABLE error_log (
       id         BIGSERIAL PRIMARY KEY,
       agent_id   TEXT NOT NULL,
       ts         TIMESTAMPTZ DEFAULT now(),
       error_type TEXT,                        -- 401·402·429·parse_error 등
       message    TEXT,
       trace      TEXT
   );

   CREATE TABLE feedback (
       id        BIGSERIAL PRIMARY KEY,
       agent_id  TEXT NOT NULL,
       user_id   UUID,
       ts        TIMESTAMPTZ DEFAULT now(),
       category  TEXT,                          -- bug·improvement·praise
       content   TEXT,
       resolved  BOOLEAN DEFAULT FALSE
   );
   ```

6. **★V3.9 — 로컬 GUI 진입점 확인** (데스크톱형 + Windows 한정)

   - 폴더 안 `시작.bat` 더블클릭 → `ui.py` 기동 → 브라우저가 `http://localhost:{포트}` 로 열리는지 실제 확인
   - 「준비 상태」 패널이 빠진 의존성을 사람 말 + 설치 링크로 안내하는지 확인 (`ModuleNotFoundError` raw 노출 0)
   - **바탕화면 바로가기는 자동 생성하지 않는다** (V3.9 — R7 폐지, PO 판단 2026-08-01). 바탕화면은 사용자가 스스로 정리하는 공간이다. 원하는 사용자를 위한 안내만 README에 한 줄: "바탕화면에 두고 싶으면 `시작.bat` 을 오른쪽 눌러 「바로 가기 만들기」 하면 된다."
   - 터미널 진입점(`run.py`)도 함께 살아 있는지 확인 (GUI 못 쓰는 환경 대비 — 병행이 원칙)

   **★ Windows 어댑터 룰 자동 검증** (V3.5 R9 신설 → V3.9 R7 교체). 이전엔 R7이 `install_shortcut.ps1` 존재를 확인했으나, 바로가기 의무 폐지로 **로컬 GUI 존재 확인으로 교체**했다. 나머지 6개 룰은 그대로 유지:

   ⚠️ **이 스크립트를 파일로 저장할 때는 반드시 UTF-8 BOM 포함.** BOM 없이 저장하면 Windows PowerShell 5.1(한국 로캘)이 cp949로 파싱해 `Unexpected token ')'` 로 죽는다 — 스크립트가 조용히 안 돌아간다. **`.bat`은 BOM 없이, `.ps1`은 BOM 포함 — 정반대다.**
   저장: Python `open(path,"w",encoding="utf-8-sig")` / PowerShell `New-Object System.Text.UTF8Encoding($true)`.

   ```powershell
   # tools/verify_windows_adapter.ps1 — Phase 6 어댑터 룰 7개를 정적 검증
   # ※ 이 파일은 UTF-8 BOM 포함으로 저장할 것 (PS 5.1 한글 파싱)
   param([Parameter(Mandatory=$true)][string]$ProjectDir,
         [switch]$HumanFacing)   # 사람 개입형이면 지정 — 룰 7(로컬 GUI) 적용

   $violations = @()
   $bats = Get-ChildItem -Path $ProjectDir -Filter *.bat -Recurse -ErrorAction SilentlyContinue

   foreach ($bat in $bats) {
       $raw = Get-Content $bat.FullName -Raw -Encoding UTF8
       if ($null -eq $raw) { $raw = "" }   # 빈 .bat 이 거짓음성으로 통과하는 것 방지

       # 룰 1: .bat 내 한글 echo·주석 금지
       if ($raw -match '[가-힣]') { $violations += "R1: $($bat.Name) contains Korean characters" }
       # 룰 2: 한글 경로 하드코딩 금지 — pushd "%~dp0" 사용
       if ($raw -notmatch 'pushd\s+"%~dp0"') { $violations += "R2: $($bat.Name) missing pushd `"%~dp0`"" }
       # 룰 3: timeout 금지 (stdin 리디렉션 환경에서 실패) → ping 대체
       if ($raw -match '(?m)^\s*timeout\s') { $violations += "R3: $($bat.Name) uses timeout (use ping -n N 127.0.0.1 > nul)" }
       # 룰 4: PYTHONUTF8 / PYTHONIOENCODING 강제
       if ($raw -notmatch 'PYTHONUTF8' -or $raw -notmatch 'PYTHONIOENCODING') { $violations += "R4: $($bat.Name) missing PYTHONUTF8/PYTHONIOENCODING" }
       # 룰 5: chcp 65001
       if ($raw -notmatch 'chcp\s+65001') { $violations += "R5: $($bat.Name) missing chcp 65001" }
       # 룰 7 짝 — .bat 은 BOM 없는 UTF-8 이어야 한다 (cmd 가 BOM 을 명령으로 오인)
       $head = [System.IO.File]::ReadAllBytes($bat.FullName)[0..2]
       if ($head[0] -eq 0xEF -and $head[1] -eq 0xBB -and $head[2] -eq 0xBF) { $violations += "R1b: $($bat.Name) saved with BOM (must be BOM-less UTF-8)" }
   }

   # 룰 6: Python 스크립트 stdout/stderr UTF-8 재구성
   Get-ChildItem -Path $ProjectDir -Filter *.py -Recurse -ErrorAction SilentlyContinue | ForEach-Object {
       $py = Get-Content $_.FullName -Raw -Encoding UTF8
       if ($null -eq $py) { $py = "" }
       if ($py -match 'print\(' -and $py -notmatch 'reconfigure\(encoding') {
           $violations += "R6: $($_.Name) prints without sys.stdout.reconfigure(encoding=...)"
       }
   }

   # 룰 7 (★V3.9 교체 — 구 R7 install_shortcut.ps1 존재 확인 폐지): 사람 개입형이면 로컬 GUI 필수
   if ($HumanFacing) {
       if (-not (Test-Path "$ProjectDir\ui.py"))         { $violations += "R7: ui.py missing (local web GUI is mandatory for human-facing agents)" }
       if (-not (Test-Path "$ProjectDir\ui\index.html")) { $violations += "R7: ui/index.html missing" }
       if (Test-Path "$ProjectDir\install_shortcut.ps1") { $violations += "R7: install_shortcut.ps1 present (desktop shortcut generation was retired in V3.9)" }
   }

   if ($violations.Count -gt 0) { $violations | ForEach-Object { Write-Warning $_ }; exit 1 }
   Write-Host "Windows adapter rules 1-7: OK"; exit 0
   ```

   이 스크립트는 **Phase 7 V1가 호출**한다 (제조자 직접 호출 금지 — 자기검증 회귀). 위반 시 Phase 6 어댑터 본체 재조립.

   ⛔ **`-HumanFacing` 전달은 선택이 아니다.** Phase 1 발굴 항목 11(사용자 층) 답변이 **②(일반인·전문직 실무자)** 이거나 **④(모르겠어요 → ②로 자동)** 이면 호출 시 `-HumanFacing` 을 **반드시** 넘긴다. 스위치를 빠뜨리면 룰 7이 잠자고 **GUI 없는 출하가 조용히 통과** — V3.9가 막으려던 바로 그 사고다. V1 prompt에 요소 11 답변값을 명시 전달하고, 출하 보고서 QC 항목에 `HumanFacing: true/false + 근거(요소 11 답변)`를 기록한다.
   ⚠️ 룰 7이 검사하는 것은 **파일 존재**뿐이다. `ui.py`·`ui/index.html` 필수 요건(`0.0.0.0` 금지·토큰 쿠키·CDN 금지 등)은 정적으로 안 잡힌다 — 빈 껍데기 `ui.py` 도 통과한다. 내용 검증은 **Phase 7-3 브라우저 클릭 검증**이 담당한다. 둘 다 통과해야 출하.

## Phase 9. 운영·개선 — 피드백 루프 (V3.0 신설) ★

**출하는 끝이 아니라 운영의 시작이다.** Phase 9는 자율 루프 — 일상 운영 중 수집된 데이터가 다음 사이클의 Phase 1로 회귀한다.

### ★ V3.9 — 구 규격 에이전트 소급 전환 (GUI 레트로핏)

V3.9 이전 규격으로 만들어 **터미널로만 쓰는 에이전트**가 이미 나가 있다. 그것들은 자동으로 화면이 생기지 않는다 — 소급 전환이 필요하다.

- **전환 가이드**: `docs/기존-에이전트-GUI-전환-가이드.md` — 비개발자가 그대로 복붙해 Claude Code에 던지는 지시문 + 확인 체크리스트 + 문제 해결이 들어 있다. 에이전트를 받아 쓰는 사람에게 **이 문서를 함께 전달**한다
- **적용 대상 판별**: 데스크톱형 + 최종 사용자가 개발자 아님 (신규 제조와 동일 조건)
- **원칙**: 기존 터미널 진입점(`run.py`·`agent.py`)을 **삭제하지 않고 화면을 덧붙인다.** 전환은 추가이지 대체가 아니다
- **완료 판정**: 문서 생성이 아니라 **브라우저에서 실제로 눌러본 것**으로 판정한다 ("서버 200 ≠ 동작함")

### 9-1. 운영 모니터링

- **사용 로그** — usage_log·error rate·latency·비용 누적
- **이상 신호** — 가드 자주 발동 / 응답 시간 급증 / 특정 에이전트 사용률 0
- **사용자 여정 KPI** — Phase 2에서 정의한 지표를 일상적으로 추적

### 9-2. 피드백 수집

- **관리자 콘솔** — 사용자 개선 요청·버그 리포트
- **자동 수집** — 에러 로그·실패 패턴
- **PO 인터뷰** — 분기·반기 단위 정성 피드백

### 9-3. 개선 사이클 → Phase 1 회귀 (V3.1 수치 임계값 명시)

다음 **정량 임계값** 중 하나라도 충족되면 다음 사이클을 자동 트리거한다 — "일정 수준"이라는 주관 표현 금지:

**자동 트리거 조건 (OR — 하나라도 해당)**
- **에러율** 일일 평균 ≥ **5%** (직전 7일 이동평균 기준)
- **응답 시간** P95 ≥ **30초** (직전 24시간)
- **피드백 누적** "버그·개선요청" 카테고리 ≥ **5건** (직전 14일)
- **사용률 0** 에이전트 ≥ **30일** (포털 모드 — 폐기/통합 검토)
- **비용 가드 발동** 일일 ≥ **3회** (한도 설정 부적정 신호)
- **PO 정기 점검**: 매월 1일 운영 KPI 리뷰 (강제)

**트리거 발동 후 회귀 깊이 매핑**:

| 트리거 신호 | 회귀 깊이 |
|--------|----------|
| 단순 버그·문구 수정 (피드백 누적) | Phase 6 재조립만 |
| 기능 추가·부품 변경 (피드백 + 사용률) | Phase 4 재분해부터 |
| 정책·아키텍처 변경 (에러율·응답시간·정기점검) | Phase 2 MBO 재승인부터 |
| 새 에이전트 추가 (포털) | Phase 1c 추가 라운드 → Phase 4 → Phase 6 |
| 사용률 0 에이전트 폐기 결정 | Phase 8 자산 갱신 + Phase 9 폐기 절차 |

트리거 발동 주체 — 자동 모니터링 시스템(usage_log·error_log)이 임계값 도달을 감지하면 관리자 콘솔에 알람을 띄우고, PO가 회귀 깊이를 1회 확인하여 다음 사이클을 승인한다. **자동 감지 + PO 1회 확인** 구조 — 둘 다 필수.

#### 9-3-B. 데스크톱형 (DB 없음) — 운영 루프 축소형 (V3.2 신설)

데스크톱형에서는 자동 모니터링 시스템이 없으므로 다음으로 축소:

| 항목 | 웹사이트형 (Supabase) | **데스크톱형 (DB 없음)** |
|---|---|---|
| 모니터링 데이터 | `usage_log` + `conversations` DB | **`history.json` 로컬 파일** 누적 |
| 에러 캡처 | `error_log` 테이블 | **`error.log` 텍스트 파일** (engine.py가 append) |
| 비용 추적 | `usage_log.cost_krw` 자동 합산 | **Anthropic 콘솔 직접 확인** (또는 history.json 합산) |
| 임계값 자동 감지 | 시스템 자동 알람 | **없음 — PO 수동 점검** (월 1회 정기 점검만 유지) |
| 피드백 채널 | 관리자 콘솔 | **README의 연락처 또는 GitHub Issues** |
| 트리거 발동 | 자동 + PO 확인 | **PO 정기 점검 시 수동 결정** (월 1회 history.json·error.log 검토) |
| Canary 배포 | 1 직능·소수 사용자 선행 | **새 zip 버전을 PO만 먼저 실행** → 동작 확인 후 팀원에 배포 |

데스크톱형의 운영 루프는 "사용자 자체 점검" 중심:
- engine.py가 매 호출 후 history.json·error.log에 자동 기록
- PO가 월 1회 두 파일을 열어 "이상 패턴" 확인 (반복 에러·비정상 비용·사용률 0 등)
- 이상 발견 시 Phase 1 회귀 — 같은 스킬스/*.md 수정 → 새 zip 빌드 → 재배포

**핵심**: 데스크톱형에서도 운영 루프는 "종이 위 약속"이 아니라 실제 파일·실제 점검으로 작동. 자동화만 빠지고 절차는 유지.

### 9-4. 점진적 배포 (Canary)

웹사이트형은 다음 사이클 산출물을 한꺼번에 풀지 않는다:
- **Canary** — 1 직능·소수 사용자 대상 선행 배포
- **Rollout** — 안정 확인 후 전체로 확장
- **Rollback** — 문제 발견 시 즉시 되돌릴 수 있는 경로 확보
