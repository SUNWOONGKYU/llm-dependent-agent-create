## Phase 2. 목표 정의 — mbo-천상 호출 + 승인 게이트 (★V3.22 — 양식 복제 폐지, 스킬 호출로 전환)

**목표서 양식·승인·MBO 파일 저장·결과 보고는 `mbo-천상` 스킬이 단일 출처다.** 에신은 양식을 베끼지 않고 `mbo-천상`을 호출해 그 절차를 그대로 탄다. 에신이 보태는 것은 딱 하나 — 에이전트 고유 「제조 대상 — 7대 구성요소 + 메타」 절을 목표서에 **삽입**하는 것뿐이다.

이 단계에서 에이전트 **규모(S/M/L)를 확정**한다. 배치/포털 모드는 자동으로 L (배포형·다수 에이전트·호스팅) 판정.

### 호출 규격 (에신 → mbo-천상)

| mbo-천상 단계 | 에신에서의 처리 |
|---|---|
| PHASE 1 Step 1 맥락 분석 · Step 2 스무고개 | **건너뜀** — 에신 Phase 1(10라운드 + α 문답)이 이미 수행. Phase 1 산출물(기획안·출력 대상 명세)을 mbo-천상 입력으로 넘긴다 |
| Step 3 AS-IS 조사 | 수행 — 현재 사람이 하는 방식(수작업)을 조사해 「현재 vs 목표」의 AS-IS 칸을 채운다 |
| Step 4 MBO 목표서 작성 | mbo-천상 양식(최상위 목표·현재 vs 목표·KPI·산출물·완료·검증 기준[공개본 명칭 「목표 달성 평가·검증 기준」+「자가수정 한도」]·실행 계획·리스크) **그대로** + 「최상위 목표」 바로 아래에 아래 **삽입 절**을 넣는다. 제목은 `MBO 목표서 — 에이전트 제조: {에이전트명}` |
| Step 5 PO 승인 | mbo-천상 게이트 그대로. ⛔ 승인 없이 Phase 2.5 이후 진행 절대 금지. 수정 요청 시 재제시 |
| PHASE 2 MBO 파일 저장(공개본 명칭 「목표서 파일 저장」) | **에신 작업 폴더**(Phase 0에서 지정) 루트에 `YYYY_MM_DD__HH.MM_mbo-천상_{에이전트명}.md` 저장 — 컴팩션·세션 교체 대비 |
| PHASE 2 자율 실행 | 에신 Phase 2.5 → 9 가 곧 실행 계획. 실행 계획 표의 Task = 에신 Phase 목록 |
| PHASE 3 결과 보고 | 에신 Phase 8 출하 보고서 직후 `/mbo-천상 report`(공개 설치본 `/mbo report`) 로 KPI 실측·산출물·검증 대조 → 저장한 MBO 파일 하단에 덧붙임. 자가수정 게이트(미달 시 Phase 7 QC 또는 Phase 2 재승인 회귀)도 mbo-천상 규정 따름 |

KPI 작성 시 에신 고유 제약(mbo-천상 양식 위에 얹음):
- 반드시 **사용자 여정 KPI 1개 이상** — "파일 생성"은 데이터 KPI일 뿐

## Phase 4. 분해·검증 — "정밀 선별" ★공장의 심장

> ★V3.12 부품을 채택하면 **회귀 테스트 승계표**(원본이 보장하던 행동 → 원본 테스트 → 우리 대응 테스트 → 실호출 증거)를 함께 만든다. 코드만 가져오고 검증을 두고 오면 안 된다.

**발굴물을 통째로 신뢰하지 않는다.** 작업대에 올려 부품 단위로 검증하고, 결함은 걸러낸 뒤 검증된 부품만 선별한다.

### 4-1. 입고 검사 — 후보별 5대 KPI 채점

| 지표 | 합격선 | 측정 |
|------|--------|------|
| **명료성** | Read 1회 5분 내 이해 | 사용 시점·절차·예시 존재 |
| **운용 충돌** | **0건 — 타협 불가** | 한국어 출력·보안 가드·SAL/MBO 자동감지 위반 0 |
| **최신성** | 6개월 이내 업데이트 | 커밋·릴리스·작성 날짜 |
| **의존성 부담** | npm/pip 추가 1개 이하 또는 검증된 메이저 OSS | 의존성 트리 |
| **검증 가능성** | 결과물 객관 검증 가능 | V1 투입 가능 여부 |

5개 중 4개 미만 → 후보 폐기 또는 fork. **"운용 충돌 0건"은 어떤 경우에도 타협 불가.**

### 4-2. 부품 단위 분해

후보를 통째로 채택하지 않는다. **함수·모듈·프롬프트 블록·설정 단위로 쪼개** 각각을 분류한다.

### 4-3. 안전성 진단 (주작 방식) → 걸러내기

발굴물을 위험도·안전성 관점에서 감사 (주작-sal-da 방식). 다음은 발견 즉시 제거:
- `eval()`·`exec()`·검증 없는 shell 직접 실행
- 하드코딩된 시크릿·API 키·절대경로
- PO 보안 가드 위반 (외부 드라이브 무단 접근, `.env` 노출 등)
- deprecated 라이브러리·API 의존
- 영어 강제 출력 등 한국어 운용 규칙 위반
- `href` 없는 버튼·죽은 링크 (UI 에이전트의 경우)
- 1년 이상 미유지보수 코드

### 4-5. 이중 분류 규칙 (V3.1 신설 — 🔵 ∩ 🏭 교집합 처리)

한 부품이 여러 분류에 동시 해당할 수 있다. 다음 우선순위 규칙으로 단일 레이블 부여:

```
🟢/🟡  >  🔵  >  🏭  >  🔴
```

**판정 절차**:
1. **출처 우선** — 발굴물에서 가져온 것이면 🟢/🟡 (재단 여부로 갈림). 출처가 외부면 무조건 🟢/🟡 분류가 1순위.
2. **범위 우선** — 자체 제작이지만 N 에이전트가 공유한다면 🔵 (배치/포털 모드만). 단일 모드에서는 🔵 불가.
3. **신규 제작 단독 사용** — 🏭
4. **결함** — 🔴 (다른 분류와 동시 적용 불가, 항상 거부)

**예시**:
- 비용 가드 코드를 자체 제작했고 93 에이전트가 모두 쓴다 → **🔵** (🏭 아님)
- 비용 가드를 PyPI 라이브러리로 가져와 그대로 적용 → **🟢** (🔵 아님)
- 단일 에이전트 전용 OCR 코드를 자체 제작 → **🏭** (🔵 아님)
- 단일 에이전트가 OSS OCR 라이브러리 가져와 한국어 폰트만 추가 → **🟡** (🏭 아님)

BOM 작성자는 한 부품을 두 분류에 동시 기입하지 않는다 — 단일 레이블만.

🔵 공통 인프라 부품의 예 (제작자 선행 프로젝트 93개 + claude-news-agent 사례):
- 비용 가드 3중 (per_run / per_user_monthly / monthly)
- 세션 HMAC + role 기반 권한 + 회원가입 승인
- 공급자 공통 tool round-trip (Anthropic/OpenAI/Gemini/xAI 중 **채택한 것**만 실호출 — ★V3.12)
- **LLM 폴백 체인 모듈 ★V3.5 신설 표준 자산** — 단일 키 401/402/429/credit 한도 시 자동 폴백 (예: `llm_providers.py` Claude→Gemini→GPT→Grok). (회고 사유: claude-news-agent 첫 실행 시 ANTHROPIC_API_KEY 401로 전체 멈춤 — 폴백 추가 후 정상 작동) ⚠️ **이 API-키 폴백 체인은 인프라 A(포털·서버) 런타임의 표준이다.** 인프라 B(PO 본인용 로컬)는 위 💳 원칙대로 **`claude` CLI(구독) → `codex` CLI 2차 검증**을 표준으로 하고 API-키 폴백 체인은 *배포용일 때만* 넣는다. (제작·검증은 A/B 불문 항상 구독 — API 금지.)
- 면책·디스클레이머 정책
- 첨부 처리 (Vercel 4.5MB → Storage signed URL 우회)
- 사용 로그·피드백·관리자 콘솔

배치/포털 모드는 🔵가 반드시 채워진다 — 비어 있다면 Phase 1c를 다시 점검한다.

**단일 모드 예외 (V3.5)**: 단일 모드는 원래 🔵 불가지만 **LLM 폴백 체인 모듈**(인프라 A) 또는 **CLI 호출 헬퍼 `_sub_env()`+claude/gemini CLI**(인프라 B)만은 단일 모드에서도 🏭(자체 제작)로 분류하여 반드시 포함한다. 단일 LLM 의존은 첫 출하 직후 멈춤 사고를 부른다.

## Phase 5. 설계 검증 — 작성자 자체 점검 1회 (V3.4 절차 내장 → ★V3.23 검증자 호출 없음)

### ★ 자기완결 원칙 폐지 (★V3.22 — 두 공장 동기화)

V3.4~V3.21의 "자기완결 원칙"(외부 스킬 호출 금지·외부 AI 호출 금지·내장 Subagent만 검증)은 **폐지**한다. 대신:
1. **핵심 절차는 계속 본문에 내장** — 5A 검토·평가 루브릭, 5B 진단·해체, Phase 7 QC 4단은 그대로 이 문서 안에 있다. `/review-evaluate`·`/pro-persona-debate`·`/주작-sal-da` 호출 의무는 여전히 없다.
2. **외부 연결은 정확히 2개(의무)** — 목표 관리 `mbo-천상`(Phase 0-0에서 보장, 필수) · 검증 V2 `Codex`(「검증 편제」 절, 폴백 있음). 이 둘 외 외부 **의무** 호출 없음. `/diagram-기본`·`/5times-debug-loop` 같은 **선택 보조 스킬**은 있으면 쓰고 없으면 본문에 적힌 내장 폴백으로 대체한다(공개 사용자 기준).
3. **검증 주체 = V1·V2, 단 Phase 7에서 1회** — 「검증 편제 — 작성자 · V1 · V2」 절이 단일 출처. Phase 5는 작성자 자체 점검이다.

이 폐지는 형제 공장 `/skill-create`에도 동일 적용된다(같은 날 짝 개정).

**Phase 5는 두 레이어 — 5A 검토·평가 + 5B 진단·해체**. S 규모는 5A만, M·L은 둘 다.

### 🔬 Phase 5B. 진단·해체 (SAL Grid 핵심 절차 내장) ★V3.4 신설

**review-evaluate(점수 매기기)와 다른 가치 — 산출물을 부품 단위로 해체하고 의존성·결함 지점을 카드별 진단.** M 규모 이상 적용.

#### 5B-1. 역방향 분해 — Grid 완성 (5단계)

```
[1] 구성요소 목록 파악     — BOM 부품 목록 활용
[2] 진단 Area 확정          — 4~9개 선택 (보안·운영·콘텐츠·인증·DB·성능 등)
[3] 구성요소 × Area 매트릭스 — 관련성 ≥ 0.6 셀만 유효 진단 단위
[4] 의존성 분석             — Stage 번호 (1, 2, 3...) + Stage 명칭
[5] SAL ID 확정             — S{stage}{AREA}{level} (예: S1SE1 = Stage1·보안·Level1)
```

#### 5B-2. Stage별 카드 처리 (의존성 순)

각 카드 = **진단 → 개선안 → 개선 실행 → 재진단** (한 카드에서 완결)

| 단계 | 내용 |
|---|---|
| **진단** | Status (Pass/Warning/Danger/Fail) + Issues + Evidence + Impact |
| **개선안** | Plan + Priority + Expected Effect |
| **개선** | 실행 + 적용 + Content |
| **재진단** | Re-status + Final Verdict + Remarks |

#### 5B-3. Stage Gate (다음 Stage 진입 조건)
- [ ] 현재 Stage 모든 카드 Final Verdict 확정
- [ ] Fail 카드 0
- [ ] 다음 Stage 의존성 충족

#### 5B-4. 자가 수렴 재진단 루프
Re-status가 Danger·Warning(미허용)이면 같은 카드에서 **재개선 → 재진단** 반복. Pass 또는 Acceptable까지 수렴.

#### 5B-5. P0 런타임 베이스라인 (코드 산출물 한정, 선택)
에이전트 코드가 있다면 (Phase 6 이후):
- 빌드 검증 (`py_compile`·`node --check`)
- 임포트 검증 (모듈 로드 성공)
- 스모크 테스트 (최소 1회 호출)
- 보안 헤더·스키마 일관성·환경변수 점검

### ★V3.27 설계도 갱신 규정 — 만들면서 고치고, Phase 6 마감에 확인한다

Phase 1 에서 그린 관계도·흐름도(`_개발자료/_design/{이름}_architecture.svg`)와 `plan.md` 는 **구현하면서 반드시 달라진다**(모듈 이름·판정 규칙·안 만든 기능·재시도 횟수·명령 이름). **구현이 설계와 달라지는 그 시점에**(모듈을 바꾸거나 기능을 빼거나 규칙을 바꿀 때) 작성자가 SVG·plan 을 같이 고치고, Phase 6 을 끝내기 전에 한 번 더 전체를 대조해 **구현 기준으로 SVG·plan 을 확정한다** — 화면 단계 카드 ↔ 흐름도 번호가 1:1 로 맞아야 하고, 흐름도에 있는데 안 만든 것(예: "표절 유사도")은 지운다. 갱신하지 않은 설계도는 "없는 기능을 있다고 읽게 하는" 결함이다(2026-09-17 학위논문 에이전트: 흐름도 5곳이 구현과 달랐음). Phase 7 V1 「사실 정확성」이 SVG 도 대조한다.
