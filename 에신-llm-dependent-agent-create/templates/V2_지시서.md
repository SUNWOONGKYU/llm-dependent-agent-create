## 절대 규칙
- 읽기 전용. 산출물 수정 금지. 보고서는 `_개발자료/_qc/v2_report.md` 하나만 새로 씁니다(지정된 출력 파일).
- 근거 없는 O는 X. 실행 가능한 검사(컴파일·테스트·grep·python 단위 호출)는 직접 실행.
- 브라우저 클릭(7-3)은 실행하지 않아도 됩니다 — `_개발자료/_qc/v1_ui_light.png`·`v1_ui_dark.png`·`_개발자료/_qc/smoke_ui.py`·`app/ui/index.html`·`app/ui.py`를 정적으로 대조해 V1의 7-3 판정이 타당한지 평가하십시오(라우트↔버튼 매핑, dead 버튼, needs_confirm 경로).
- 실주행 전체(`run.py run`) 금지. 완료된 `app/state.json`·DOCX를 검사합니다.
- python 실행은 `PYTHONUTF8=1`.

## 검증 대상 · 4단 QC · 5축 · 결함 등급 · 합격선
`templates/V1_지시서.md`(채운 것)의 「검증 대상」「4단 QC」「5축 채점」「결함 등급」「합격선」을 **그대로** 적용합니다(중복 기재 생략). ★ 설계 적합성(7대 구성요소 누락·흐름 끊김 등)은 Phase 5 에서 이미 검증됐으므로 다시 보지 않습니다 — 구현이 그 설계대로인지만 봅니다. **단 비가역 도구(게시·삭제·결제·전송)가 있으면 이 범위 제한을 풀고 "승인 결속 범위가 설계에 충분한가"도 직접 봅니다.**(★V4.12) 추가로 V2가 특히 볼 것:

1. **가드 우회 경로** — export_gate·목차 승인 게이트·가명화가 우회되는 코드 경로(UI 라우트·run.py·액션봇 액션)가 있는가.
2. **{{도메인 핵심 가드}}** — 우회 시나리오를 구체적으로 검토. 있으면 High.
3. **동시성·상태** — `store.py` 잠금·원자 쓰기, `ui.py` `_job` 폴링, 두 창 동시 조작 시 상태 손상 가능성.
4. **문서 ↔ 실제** — README·매뉴얼·`이번에 바뀐 것.md`·`확인이 필요한 사항 목록.md`가 코드와 어긋나는 문장.
5. **아키텍처 파일 ↔ 구현** — `_개발자료/_design/*_architecture.svg`·plan(설계서)이 코드와 같은가(없는 기능·다른 모듈명·다른 규칙).
6. **요구 값 강제 대조표 독립 재확인(★V4.11)** — `_개발자료/_qc/요구값_강제_대조표.md`의 「코드 위치」·「강제 방식」을 V1 판정과 별개로 grep·코드 읽기로 재확인. 특히 호출 한도가 재시도·폴백까지 실제로 세는지, 종료 조건이 선언한 그대로인지, 한계가 plan.md·출하 보고서·사용자 화면 세 곳에 다 고지됐는지.
7. **공격 시나리오(★V4.12)** — `templates/V1_지시서.md` 「7-4b 부속 — 공격 시나리오 직접 세우기」 절을 그대로 따른다(문구는 그 한 곳이 단일 출처, 여기서 다시 쓰지 않는다). 비가역 도구가 있으면 **작성자 위협모델 문서(plan.md 안전·실패 모드 절, `phase5_design_verify.md`)는 V2 입력에서 제외**하고 V1 보고서의 시나리오 표도 보기 전에 자기 시나리오부터 세운다. **V2 는 L 규모만 붙는다 — S·M 의 비가역 공격 시나리오는 V1 만 진다.**
